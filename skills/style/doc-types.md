# 문서 유형 가이드 (doc-types)

독자의 목적에 따라 문서(페이지)의 유형을 정하고, 유형마다 지켜야 할 요건을 정하는 원본.
`writing-style.md`가 문장을, 템플릿이 섹션 순서를 정한다면, 이 문서는 "이 문서가 독자에게
무엇을 해 줘야 하는가"를 정한다. 근거는 토스 테크니컬 라이팅 가이드 `type/` 아래 파일이다
(출처는 `writing-style.md` 끝).

## 유형과 요건 (`type/index.md`)

| 유형 | 독자의 목적 | 요건 |
|---|---|---|
| 학습 | 처음 접하고 따라 하며 흐름을 익힌다 | 목표 → 사전 준비 → 번호 단계 → 결과 확인. 예제는 끝까지 막힘없이 실행된다 (`type/learning.mdx`) |
| 문제 해결 | 특정 작업·문제를 지금 해결한다 | 맨 앞에 "사전 준비"(권한·토큰, 환경별 차이). 원인과 현상을 나눠 쓴다. 에러 메시지·로그를 원문으로 싣는다. 예제는 그대로 실행된다(형식은 `writing-style.md` §14). 대응 표의 "할 일" 칸은 행동으로 쓴다 (`type/problem-solving.mdx`) |
| 참조 | 알고 있는 기능의 세부를 찾아 적용한다 | 모든 항목이 같은 골격(엔드포인트 → 요청 → 응답 → 오류 → 예제)을 따른다. 빠진 필드가 없다. 예제가 있다. 인증처럼 미리 알아야 할 것은 앞쪽에 둔다 (`type/reference.mdx`) |
| 설명 | 원리·배경·결정 이유를 이해한다 | 무엇이 왜 필요한지부터 쓴다. 구조·흐름은 다이어그램으로 보인다. 선행 지식을 안내한다. 열거값 목록 같은 참조성 내용이 길면 참조 쪽으로 보내고 링크한다 (`type/explanation.mdx`) |

여러 유형이 섞이면 주 유형 하나를 정하고, 다른 유형의 내용은 절을 나누거나 다른
문서로 보낸다. 토스 가이드도 유형 결합을 허용한다(`type/index.md` "이 분류가 항상 정답은
아니에요").

## 템플릿별 유형과 적용 포인트

템플릿마다 가장 가까운 유형과, 그 유형 요건이 이 템플릿에서 무엇이 되는지다. "유형 밖"은
토스 유형이 겨냥하지 않는 업무 문서다. 이런 문서에는 유형 요건 없이 문장 규칙
(`writing-style.md`)만 적용한다.

| 템플릿 | 유형 | 적용 포인트 |
|---|---|---|
| `bug_ticket` | 문제 해결 | "실제 동작"(현상)과 "원인 가설"(원인)을 섞지 않는다. 증거에는 에러 메시지·로그를 원문으로 싣는다. 환경 차이로 재현이 갈리면 환경 절에 적는다. 회피책은 독자가 할 행동으로 쓴다 |
| `diff_explanation` | 설명 | Background가 선행 지식 안내다. Intuition은 다이어그램과 설명용 예시가 중심이다. 변경 이유(왜)를 Code 앞에 둔다 |
| `pr_retrospective` | 설명 | 변경 내용보다 배경/동기를 먼저 쓴다. 구조가 바뀌었으면 전후를 다이어그램으로 보인다 |
| `proposal` | 설명 | 독자가 얻을 가치(기대효과)를 Abstract에 먼저 쓴다. 문제 → 제안 순서를 지키고, 검토한 대안 표로 선택 이유를 납득시킨다 |
| `experiment_report` | 설명 | Abstract에 알아낸 것을 먼저 쓴다. 방법은 같은 측정을 다시 할 수 있을 만큼 구체적으로 쓴다(학습 유형의 "막힘없이 따라 하기"). 결과는 표로 쓴다 |
| wiki README (write-wiki) | 설명 | 결정과 근거가 중심이다. 실험 결과는 REPORT 링크로 보낸다 |
| wiki REPORT (write-wiki) | 설명 | 질문 → 방법 → 결과 → 결정. 방법은 다시 할 수 있을 만큼 구체적으로 쓴다 |
| `general`, `default` | 작성 전에 정한다 | 독자의 목적으로 네 유형 중 하나를 고르고 그 요건을 따른다 |
| `doc_set` | 페이지마다 정한다 | 페이지마다 유형 하나. 부록(설계 결정·용어)은 `../templates/doc_set.md`가 정한다 |
| `issue_ticket`, `pull_request`, `proposal_chat`, `meeting_minute`, `ideation` | 유형 밖 | 문장 규칙만 적용한다. 행동 요건은 review-document의 실행가능성 축이 본다 |
