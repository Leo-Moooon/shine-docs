# 검증 리뷰어 체크리스트 (verification-checklist)

검증 리뷰어가 초안을 판정할 때 순회하는 질문 목록. 여기는 판정용 질문만 두고, 규칙 원문은
`../review-document/SKILL.md`가 단일 원본이다.

이 목록은 **문서 밖 자료를 들고 대조해야 판정되는 축**만 담는다. 문서 텍스트만으로 판정되는
축(가독성·구조, 내부 일관성, 독자 적합성, 표기, 실행가능성)은 `review-checklist.md`를
순회하는 가독성 리뷰어의 몫이다.

외부 조회 권한(코드베이스 탐색, 웹검색, URL fetch)은 이 리뷰어에게만 있다.

## 기준선 확인 (순회 전 1회)

- [ ] 대조할 근거가 무엇인지 확정했는가? (원문 / 대화 맥락 / 코드베이스 / 없음)

**근거가 없으면 사실성 항목은 순회하지 않는다.** 코드베이스가 있으면 참조 유효성만 보고,
문서가 스스로 검증 가능한 주장을 했을 때만 확인해 질문으로 올린다. 기준선 없이 "틀린 것
같다"를 남발하지 않는다.

## 사실성 — 하드 게이트

하나라도 "예"가 나오면 무조건 반려한다. 통과할 수 없다.

- [ ] 근거에 없는 내용이 유추로 들어가 있는가?
- [ ] 근거로 뒷받침되지 않는 주장이 확정 서술되어 있는가?
- [ ] toy data·가짜 데이터가 "설명용 예시" 라벨 없이 실제 데이터처럼 제시되어 있는가?
- [ ] 근거에서 3단논법을 넘는 비약으로 도출된 결론이 있는가?
- [ ] 근거의 수치·날짜·이름이 산출물에서 바뀌어 있는가?

## 참조 유효성

문서가 가리키는 대상이 실재하는지 확인한다. 확인 수단이 없는 항목은 반려하지 않고 질문으로
남긴다.

- [ ] 파일 경로가 실재하는가?
- [ ] 코드 심볼(함수·클래스·설정 키)이 실재하고 문서의 설명과 맞는가?
- [ ] URL이 살아 있고 문서가 말하는 내용을 담고 있는가?
- [ ] 티켓번호·PR번호가 문서가 말하는 대상과 일치하는가?

## 공란 규율

호출부 스킬의 공란 규칙이 지켜졌는지 본다. **근거가 없어 비어 있는 필수 섹션은 정상
동작이므로 감점하지 않는다** — 위반은 아래 두 방향뿐이다.

- [ ] 필수 섹션이 비어 있는데 무엇이 없어서 비었는지 한 줄이 남아 있지 않은가?
- [ ] 근거가 없는데도 그럴듯하게 채워진 섹션이 있는가? (그렇다면 사실성 항목으로 올린다)
- [ ] 근거가 없어 생략해야 할 선택 섹션이 빈 제목만 남긴 채 방치되어 있지 않은가?

## 판정할 때 하지 않는 것

- 문서를 더 풍부하게 만들라고 요구하지 않는다. 판단 근거는 항상 "근거 ↔ 산출물" 대조다.
- 웹검색으로 찾은 사실을 반려 근거로 쓰지 않는다. 원문 자체가 틀린 경우는 산출물의 결함이
  아니므로 "원문의 결함"으로 따로 표시한다.
