# Document Refactor

임의의 문서를 유형에 맞는 논리 구조로 재배치해 가독성 높은 산출물(HTML/MD)로 만든다.

## 절대 규율 — "자명한 사실만"
- 원문에서 확인 가능한 내용 + 3단논법 수준의 당연한 도출만 취급한다.
- 맥락상 그럴듯하다는 이유로 알려지지 않은 사실을 유추하는 것은 **절대 금지**.
- 설명을 돕는 toy data/가짜 데이터는 허용하되 반드시 "설명용 예시(원문 밖)"로 라벨링한다.

## 실행 역할
- **메인** = 사용자와 대화하며 파이프라인을 조율하는 오케스트레이터 컨텍스트.
- **서브에이전트** = 메인이 별도 컨텍스트로 분리 실행하는 역할(작성자·리뷰어 등). 분리 실행이 어려우면 최소한 역할별로 컨텍스트를 명확히 분리해 수행한다.
- **리뷰어 독립성(중요)**: 4단계 Review의 두 리뷰어는 3단계 Draft를 작성한 작성자와 **분리된 컨텍스트**여야 한다. 작성자가 자기 초안을 스스로 검토하면 사실성 하드 게이트가 자기검토로 붕괴한다.

## 1. Intake (메인)
- 입력을 원문 텍스트로 확보한다: 붙여넣기는 그대로, 파일경로는 읽고, URL은 가용한 fetch/커넥터로 가져온다(예: Notion). 커넥터가 없으면 사용자에게 원문을 붙여넣어 달라고 요청.
- **모드**: 사용자가 HTML/MD를 지정했으면 따르고, 지정이 없으면 **인터랙티브 선택지(클릭형)로 묻는다** (HTML / MD).
- **저장 위치**: 기본은 현재 작업 디렉토리. 원하는 위치를 **인터랙티브 선택지로 확인한다** (현재 디렉토리 / 다른 경로 지정). 파일명에 날짜 접두사를 붙이지 않는다.
- **인터랙티브 규칙**: 초기 의사결정(모드·저장 위치·아래 Classify의 유형 확인)은 자유 텍스트 질문 대신 **클릭형 선택지 도구**(harness의 AskUserQuestion 등)로 제시한다. 도구가 없는 환경이면 텍스트로 폴백한다. 사용자가 처음부터 값을 명시했으면 그 결정은 다시 묻지 않는다.

## 2. Classify (서브에이전트)
- 공용 템플릿 풀 `../templates/`(이 스킬 디렉토리 기준, 레포의 `skills/templates/`)의 파일 목록과 각 파일 제목 아래의 설명 줄만 훑어 유형을 추정한다.
- 추정한 유형을 **인터랙티브 선택지(클릭형)로 확인받는다**: 「이 유형으로 진행」 / 「다른 유형 선택」(다른 템플릿 목록 제시) / 「확인 없이 바로 진행(bypass)」. 사용자가 bypass를 고르거나 미리 "확인 없이 진행"을 요청했으면 이 확인을 건너뛴다.
- 확정된 템플릿 파일 **하나만** 정독한다.
- 어떤 템플릿에도 맞지 않으면 `default.md`로 폴백하거나, 원문을 보고 적절한 섹션을 즉석 구성한다.

## 3. Draft = 작성자 서브에이전트
- 작성 전에 공용 스타일 가이드 `../style/writing-style.md`(레포의 `skills/style/`)를
  정독한다 — 특히 최우선 규칙 "최종 상태만 flat하게". 원문이 과정 서술(작업 로그)로
  쓰여 있어도 산출물의 논리 구조는 최종 내용 기준으로 재편한다.
- 원문 내용을 선택된 템플릿의 섹션에 재배치한다(=PR 초안).
- **분할 신호**: 재배치 결과가 분할 신호(스타일 가이드 §11 — H4 이상, 독립 주제 2개
  이상)에 걸리면 그대로 진행하지 말고 메인이 **인터랙티브 선택지로 묻는다**:
  「한 파일 유지(목차로 탐색)」 / 「개요(허브) 문서 + 하위 문서로 분할」. 분할을 고르면
  개요 파일이 진입점이 되고 각 하위 파일을 상대 링크로 연결한다. 사용자가 이미 단일
  문서를 명시했으면 묻지 않는다.
- **공란 규칙**: 필수 섹션인데 원문에 근거가 없으면 공란으로 남긴다(문서가 안 다루는 논점을 드러냄). 선택 섹션인데 근거가 없으면 생략한다.
- toy data에는 "설명용 예시(원문 밖)" 라벨을 붙인다.
- 유추 금지 규율을 지킨다(절대 규율 참조).

## 4. Review (PR 패턴, 최대 3라운드)
초안을 두 리뷰어 서브에이전트가 검토하고, 작성자가 코멘트를 반영한다. 승인될 때까지 루프하되 최대 3라운드.

**리뷰 기준(중요): 리팩토링의 품질 = 원문 대비 충실도를 본다. 산출물의 독립적 완성도가 아니다. 판단 근거는 항상 "원문 ↔ 산출물" 대조다. 원문에 근거가 없어 공란인 섹션은 정상 동작이며 결함이 아니다 — 절대 감점하지 않는다.**

- **[사실성 리뷰어] — 하드 게이트.** 원문에 없는 유추, 무근거 주장, 라벨 없는 toy data, 3단논법을 넘는 도출을 찾는다. 하나라도 있으면 무조건 반려(머지 불가).
- **[가독성·구조 리뷰어].** 섹션 배치·흐름·시각화가 *원문에 있는 내용*을 충실·명료히 드러내는지 본다. 문서를 더 풍부하게 만들라는 게 아니다. 문체는 `../style/writing-style.md` 기준으로 `../style/review-checklist.md`를 순회하며 검토한다 — 특히 과정 서술이 본문 구조에 남은 것, bullet 한줄 나열, 설명 없는 어려운 용어는 반려 사유.
- 3라운드 안에 사실성 리뷰어가 승인하지 못한 항목, 미반영 코멘트는 산출물의 Appendix(Audit Trail)에 "미해결 이슈"로 기록한다.

## 5. Render (메인/서브)
승인된 초안을 모드에 맞춰 산출한다.

### 산출물 구조 (모드 공통)
- **본문**: 템플릿 섹션 순서대로. Abstract가 맨 앞.
- **Quiz**: 이해도 점검용. 원문 사실에 근거한 문항만. (HTML=인터랙티브 객관식, MD=접이식 Q&A)
- **Appendix — Audit Trail**: (1) 리뷰에서 반려된 유추/걸러진 내용, (2) 3라운드 소진 시 미해결 이슈, (3) 원문 근거 부재로 공란 처리된 섹션 목록.

### HTML 모드
- 자기완결 HTML 한 파일(CSS·JS 인라인). 한 페이지 + 목차. 반응형.
- ASCII 다이어그램 금지 — HTML 도형/표/리스트로 그린다.
- 코드블록은 `<pre>` 또는 `white-space: pre-wrap`.
- Quiz는 클릭 시 정답 여부·피드백을 보여주는 인터랙티브 객관식.

### MD 모드
- 마크다운 네이티브 시각화(표, mermaid 등).
- Quiz는 `<details>` 접이식 Q&A.
